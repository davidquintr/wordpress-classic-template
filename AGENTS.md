# WordPress Classic Template — agent guide

Classic WordPress theme that replicates the Next.js portfolio (`portfolio-new`). All content is built with **ACF PRO dynamic blocks** (flexible content field `blocks`), the **classic editor**, **vanilla CSS** and **TypeScript** bundled with webpack.

## Priorities (in this order)

1. **Performance.** Every byte and every request counts. Before adding anything, consider its loading cost and look for the lightest option.
2. **ACF dynamic blocks.** A new section is an ACF layout with its own PHP template and CSS file. No Gutenberg, no shortcodes, no HTML pasted into the editor.
3. **Fidelity to the original.** Anything that exists in `portfolio-new` must look the same: same sizes, colors and breakpoints.
4. **Simplicity.** No runtime dependencies: no jQuery, no frameworks, no CDNs.

## House rules (mandatory)

### English first

- **Everything is written in English:** code, identifiers, comments, documentation (including this file), commit messages and default UI strings.
- UI strings are English and translatable with the `wordpress-classic-template` text domain (`__()`, `esc_html_e()`…). Other languages come from translations, never from hardcoded strings.
- When you touch a file that still has text in another language, translate it.

### Comments only at the top of the file

- **No inline comments.** Don't write `//`, `/* */` or `<!-- -->` inside the code body, not even next to a line or above a function.
- Each file opens with **one header comment** that explains its purpose, where it is used (template, CSS file, ACF layout), its functions or parts, and any non-obvious decision. Anything you would have explained inline goes there.
- PHP: the docblock right after `<?php`; page templates keep `Template Name:` inside it. CSS/JS/TS: a `/* … */` or `/** … */` block on the first lines.
- When you change a file, update its header so it stays accurate.

### Class names with single hyphens

- `block-introduction-title`, `button-small`, `site-header-home`. **Never `__` or `--` in class names.** States use `is-active`, `is-open`.
- CSS custom properties (`--color-…`) are the only exception, because the syntax requires it.

## Performance rules (mandatory)

- **Nothing from CDNs.** Fonts, icons and scripts live in the theme.
- **Fonts:** `.woff2` only, latin subset, `font-display: swap`, registered in `theme.json`. Preload only the ones visible on first paint (`wordpress_classic_template_preload_assets()` in `functions.php`).
- **Icons:** inline Tabler SVGs (`assets/icons/`) through `wordpress_classic_template_icon()`. Never icon fonts.
- **Images:**
  - Above the fold: `loading="eager"` and `fetchpriority="high"`; everything else `loading="lazy"`. Always with `width`/`height`.
  - Key images go through `wordpress_classic_template_picture()` (`inc/images.php`): AVIF/WebP crops at the exact displayed size, choosing the lightest format.
  - With `wp_get_attachment_image()`, pass a real `sizes` (`'48px'`, not `100vw`).
  - Don't register global sizes with `add_image_size()` for a single image: they would be generated for every upload.
- **CSS:** a single `dist/styles.css`, minified in production. No extra stylesheets per template.
- **JS:** a single `dist/script.js`, enqueued deferred in the footer. If CSS can solve it, don't write JS.
- **Queries:** inside blocks use the data ACF already returns (relationship fields return `WP_Post` objects). Avoid extra `WP_Query` and never use `posts_per_page => -1` in public listings.
- **Not part of the theme:** WooCommerce, the block editor, Gutenberg patterns, Font Awesome, Tailwind or any UI library.

## Structure

```
functions.php                 Theme supports, menus, asset enqueue, preloads, classic editor, login/registration
inc/
  template-tags.php           PHP components: icon(), button(), link(), field(), social networks
  blocks.php                  ACF block dispatcher
  images.php                  Optimized <picture> (on-demand AVIF/WebP)
  class-navigation-walker.php Bottom menu rendered as buttons
template-parts/
  blocks/<layout>.php         One template per ACF layout
  components/<name>.php       Reusable pieces (e.g. project-card)
  content-archive.php         Listing item (index, archive, search)
header.php / footer.php       Identity header (ACF options) and fixed bottom navigation
front-page.php, page.php      Render the page's ACF blocks
single.php, index.php, archive.php, search.php, 404.php, comments.php
page-login.php, page-register.php   Custom login and registration (login.css on its own)
styles/                       CSS sources (see below)
scripts/                      TypeScript sources
assets/fonts | icons | images Files served as they are
dist/                         Generated by webpack (not versioned)
theme.json                    Palette and fonts (source of truth)
```

Conventions:
- **Prefix:** `wordpress_classic_template_` for PHP functions; `wordpress-classic-template-` for handles and the text domain.
- **Escaping:** escape everything you print (`esc_html`, `esc_attr`, `esc_url`, `wp_kses_post` for WYSIWYG fields).

## ACF and dynamic blocks

The field groups live in the database (exported from ACF):

| Group | Location | Fields |
|---|---|---|
| Global Fields | Options page `global` | `avatar` (image), `identity` (group: `name`, `role`), `social_medias` (repeater: `url`, `media`) |
| Page Content | Post type `page` | `blocks` (flexible content) |
| Project Content | Post type `project` | `icon` (image) |

`blocks` layouts:

| ACF layout | Template | CSS |
|---|---|---|
| `introduction_section` (`title`, `description`) | `template-parts/blocks/introduction-section.php` | `styles/blocks/introduction-section.css` |
| `section_heading` (`title`, `description`, `links` → `link`) | `template-parts/blocks/section-heading.php` | `styles/blocks/section-heading.css` |
| `project_listing` (`projects`, relationship to `project`) | `template-parts/blocks/project-listing.php` | `styles/blocks/project-listing.css` |

### How blocks render

`front-page.php` and `page.php` call `wordpress_classic_template_render_blocks()` (`inc/blocks.php`). It loops over `have_rows('blocks')` and includes `template-parts/blocks/<layout>.php` for each row, turning the underscores of the layout name into dashes. Pages without blocks fall back to `the_content()`.

Inside a block template:
- Read fields with `get_sub_field()`.
- `$args['index']` is the block position on the page. The first `introduction_section` renders its title as the `<h1>`.
- Read global options with `wordpress_classic_template_field('name', 'option')`, which doesn't break if ACF is disabled.

### Adding a new block

1. **ACF:** add the layout to the `blocks` field (*Page Content* group) with a `snake_case` name, e.g. `tech_listing`.
2. **Template:** create `template-parts/blocks/tech-listing.php` with a header comment naming its layout and its CSS file. The dispatcher finds it automatically.
3. **Styles:** create `styles/blocks/tech-listing.css` and import it in `styles/main.css`, in the *Blocks* group.
4. **Container:** root class `block-tech-listing`, with `max-width: var(--wide-max-width)`, `margin-inline: auto` and `padding-inline: var(--gutter)`. The space between blocks comes from `.site-main` (`gap: var(--section-gap)`); don't add outer margins.
5. **Components:** if a piece repeats (cards, buttons), move it to `template-parts/components/` or `inc/template-tags.php`, with its CSS in `styles/components/`.
6. **Update the tables** in this guide.

### WYSIWYG content

Wrap it in `.rich-text` (`styles/components/rich-text.css`). It mirrors the Tailwind Typography `prose` styles of the original site, and each block only adjusts the paragraph size. Editor content must be clean text: no `<div class="…">` copied from the Next site.

## CSS

Everything is hand-written CSS: no Tailwind, no preprocessors. The entry point is `styles/main.css`, which imports in this order:

```
tokens.css      Variables (theme.json aliases + spacing, radius, motion)
basic.css       Reset (Tailwind preflight equivalent), html/body, .site-main, .icon, .screen-reader-text
components/     Reusable pieces: button, tooltip, rich-text, project-card
parts/          header, navigation (footer), background (page layers), comments
blocks/         One file per ACF layout
templates/      One file per WordPress template (front-page, page, single, index, archive, search, 404)
```

Rules:
- **One file per piece.** Every block, template, part and component has its own `.css`. Import new files in `main.css`, in their group.
- **Root class prefixes:** `block-` for blocks, `template-` for templates, `site-` for global parts. Components use their name (`button`, `project-card`).
- **Tokens, never raw values:** `var(--color-primary-50)`, `var(--font-heading)`, `var(--radius-md)`, `var(--gutter)`. Transparency: `color-mix(in oklab, var(--color-x) 50%, transparent)`.
- **Mobile first.** `min-width` breakpoints: `640px` (sm), `768px` (md), `1024px` (lg), the same as the original.
- **Background:** the `<body>` must not get a `background` or a `z-index`; it would hide the layers in `parts/background.css` (pseudo-elements with negative `z-index`).
- **`url()` paths** are relative to `dist/styles.css` (e.g. `../assets/images/x.webp`). Webpack doesn't rewrite them (`css-loader` with `url: false`), so the URL stays stable and can be preloaded from PHP.
- **Animations:** only hover transitions for now. If you add animations, respect `prefers-reduced-motion`.

## TypeScript

- Entry point `scripts/index.ts`, compiled to `dist/script.js`.
- **One module per feature** (`scripts/<feature>.ts`), imported from `index.ts`.
- **Never import CSS from TS.** Styles only come in through `styles/main.css`. Webpack has both entries (`entry: ['./scripts/index.ts', './styles/main.css']`).
- **The script loads on every page** (deferred), so each module checks that its element exists before using it:
  ```ts
  const element = document.querySelector<HTMLElement>(".block-tech-listing");
  if (element) {
      element.classList.add("is-ready");
  }
  ```
- **Hook JS to the DOM with the same classes as the CSS**, or with `data-*` attributes for non-visual behavior. Toggle a class (`is-active`, `is-open`) instead of writing inline styles from JS.
- **No runtime dependencies.** Justify the weight of any library before adding it.

## theme.json

The **source of truth** for the palette and fonts. WordPress turns it into `--wp--preset--*` variables and the `@font-face` rules.

- **`settings.color.palette`:** the palette (`alternative-*`, `primary-*`, `secondary-*`). To change or add a color:
  1. Edit it in `theme.json`.
  2. Add its alias in `styles/tokens.css` (`--color-x: var(--wp--preset--color--x)`).
  3. Always use the alias in CSS, never the `--wp--preset--…` variable directly.
- **`settings.typography.fontFamilies`:** Poppins (body) and variable Roboto Slab (headings). Each `fontFace` has `src` with `file:./assets/fonts/…`, `fontDisplay: swap` and a latin `unicodeRange`. To add a weight:
  1. Download the latin `.woff2` (Fontsource) into `assets/fonts/<family>/`.
  2. Add its `fontFace` entry.
  3. Preload it only if it is visible on first paint.
- **`styles`:** base font (`--font-body`) and heading font (`--font-heading`).
- **Don't add** block-editor-only settings (`fontSizes`, `spacing`, `layout`, `appearanceTools`, `patterns`): the theme uses the classic editor and they would generate unused CSS.
- **`page-login.php`** doesn't call `wp_head()`, so it prints the fonts and global styles itself (`wp_print_font_faces()` and `wp_get_global_stylesheet()`).

## Icons

- **Source:** Tabler Icons (outline, MIT) in `assets/icons/<name>.svg`, without `width`, `height` or `class` attributes.
- **Usage:** `echo wordpress_classic_template_icon('download');`. Icons inherit the text color (`currentColor`) and measure `1.25em` (`1em` inside buttons).
- **New icon:** copy it from the `@tabler/icons` package (`icons/outline/<name>.svg`) and strip those attributes.
- **Bottom menu:** each menu item has a class `icon-<name>` in its *CSS Classes* field (Appearance → Menus). It currently uses `icon-home`, `icon-briefcase`, `icon-world-star` and `icon-article`. Those icons don't appear in the code, but **don't delete them**.
- **Social networks:** the ACF `media` value maps to an icon in `wordpress_classic_template_social_networks()`.

## Commands

```bash
npm install --include=dev   # --include=dev is required when the environment has NODE_ENV=production
npm run watch               # development: rebuilds on save, not minified
npm run build               # production: minified CSS and JS
```

`dist/` is not versioned: run `npm run build` before deploying.

## Verification before calling something done

1. **PHP syntax** of every file you touched. Local's PHP needs its bundled libraries:
   ```bash
   B=~/.config/Local/lightning-services/php-8.2.29+0/bin/linux
   LD_LIBRARY_PATH="$B/shared-libs:$B/lib" $B/bin/php -l file.php
   ```
   Run `curl` in a separate command, without that `LD_LIBRARY_PATH`, because it breaks `curl`.
2. **Build:** `npm run build` without errors.
3. **The site responds without PHP errors:** `curl -s http://worpress-classic.local/ | grep -c "Fatal error\|<b>Warning"` must print `0`.
4. **House rules:** English only, no inline comments, no `__`/`--` in class names.
5. **If you changed something visual,** compare it with the original (`portfolio-new`, at `http://localhost:3000` when it is running) at 1280px and 390px.
